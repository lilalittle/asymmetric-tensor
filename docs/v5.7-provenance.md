### Why the deletion-only split is not ignored

A full audit of the equivalent predecessor tree with the split and wrapping
commits ignored found **396 wrong original-line mappings**. Although the split
is deletion-only, Git's ignore heuristic selected unrelated lines. For example,
`Applications/MechanicsMass.lean:48` maps to canonical raw line 1988:

```lean
    u_P_c * u_dimless = u_P_c := by
```

Ignoring the split instead selected line 535 in the byte-identical module copy:

```lean
noncomputable def h_projector (u : V4) : T2 :=
```

The displayed author was Binyamin, but the actual line was wrong. The split is
therefore deliberately absent from the ignore file. Its unchanged revision and
this retained failure evidence are sufficient reason not to retry that exclusion
on the reconstructed history. Neither an expected author name nor the absence
of an unblamable marker can certify provenance.

## Reproduce the accepted full-file checks

Use Git 2.49.0 for the recorded counts. Other Git versions may make different
heuristic choices; validate actual original content before accepting changes.
The source map's recorded production head is immutable. The current ignore file
adds only the two v5.7 revisions described above to the previous manuscript entry.

```sh
git blame 9b8c32d0f30ef74ca71f76bdc9b6a05ab2360b35 -- AsymmetricTensor/Model.lean
git -c blame.markIgnoredLines=true -c blame.markUnblamableLines=true \
  blame --ignore-revs-file .git-blame-ignore-revs \
  9b8c32d0f30ef74ca71f76bdc9b6a05ab2360b35 -- AsymmetricTensor/Model.lean
git -c blame.markIgnoredLines=true -c blame.markUnblamableLines=true \
  blame -w -M -C -C -C --ignore-revs-file .git-blame-ignore-revs \
  9b8c32d0f30ef74ca71f76bdc9b6a05ab2360b35 -- AsymmetricTensor/Model.lean
```

This standalone check reconstructs the canonical coordinates for every module,
reads the returned origin objects, and checks both accepted modes and all
scaffolding origin tuples. LF splitting is intentional: some historical files
contain vertical-tab characters which Python's broader `splitlines()` treats as
extra lines, unlike Git's line numbering.

```sh
python3 - <<'PY'
import json, re, subprocess
from functools import lru_cache
m = json.load(open('docs/v5.7-source-map.json'))
head = m['mapped_production_head']
def git(*args):
    return subprocess.check_output(['git', *args]).decode()
@lru_cache(None)
def lines(commit, path):
    return git('show', commit + ':' + path).split('\n')
def norm(text):
    return ''.join(text.split())
def blame(path, flags):
    result = {}
    for text in git('blame', '--line-porcelain', *flags, head, '--', path).split('\n'):
        match = re.fullmatch(r'([0-9a-f]{40}) (\d+) (\d+)(?: \d+)?', text)
        if match:
            commit, original, dest = match.groups()
        elif text.startswith('filename '):
            original_path = text[9:]
        elif text.startswith('\t'):
            result[int(dest)] = (commit, original_path, int(original))
    return result
raw = lines(m['source_commit'], m['source_path'])
for name, flags in [('default', []), ('copy-aware', ['-w', '-M', '-C', '-C', '-C'])]:
    count = 0
    for path, module in m['modules'].items():
        normal = blame(path, flags)
        ignored = blame(path, flags + ['--ignore-revs-file', '.git-blame-ignore-revs'])
        current = lines(head, path)
        for lo, hi, source_lo, source_hi, kind in module['ranges']:
            for dest in range(lo, hi + 1):
                if source_lo is None:
                    assert normal[dest] == ignored[dest], (path, dest, 'scaffold changed')
                elif current[dest - 1].strip():
                    source = source_lo + dest - lo
                    commit, old_path, old_line = ignored[dest]
                    assert norm(lines(commit, old_path)[old_line - 1]) == norm(raw[source - 1]), (path, dest)
                    count += 1
    assert count == 5195, count
    print(name, count, 'matching origin lines; zero scaffold changes')
PY
```
