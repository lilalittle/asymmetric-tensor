## Status key

- **proved_identity**: kernel-checked algebra for the exact implemented objects, with physical limitations stated.
- **conditional_implication**: conclusion follows from supplied model equations or other substantive hypotheses.
- **definition**: a model expression is introduced, not derived.
- **assumption**: the manuscript relationship enters as a premise or modeling identification.
- **open_derivation**: required objects or proof are absent; related scalar stand-ins may exist.
- **specification_target**: the conclusion is supplied as `h_target` and returned unchanged.
- **conjecture**: roadmap claim without an implemented construction or proof.
- **known_mismatch**: the paper interpretation/formula does not match this source snapshot.

Labels apply to the scope described in each note. A proved identity does not validate the surrounding physical interpretation. An open derivation does not claim the paper is false. A correct implication with an assumed target is not an invalid Lean proof.

## Assumptions and missing constructions

The only custom axioms reported transitively are `c`, `l_p`, `hbar`, and their three positivity axioms. Standard logical axioms (`propext`, `Classical.choice`, `Quot.sound`) are listed separately. No audited declaration depends on `sorryAx` or the removed universal conservation axiom. This is a complete declaration audit for the identified module snapshot, not a consistency proof or a claim that physical assumptions are limited to six axioms. The nine body-less opaque fields, theorem hypotheses, parameterized operators and model definitions also carry modeling choices. See [scope and unspecified symbols](formalization-status.md#assumptions-and-unspecified-symbols).

Omissions in this historical snapshot include covariant assembly and a connection, Noether currents, full-matrix spectra, physical fluid and wave PDE derivations, variational/action/path integrals, integer quantization, spinor representations, and gauge structures. The [current section scope map](formalization-status.md#section-by-section-status) separately tracks later changes. Numbering in old Lean comments is not used as mapping evidence.

## Reproduction and stale-evidence guard

On the current repository, validate the historical archives and deterministic artifacts explicitly:

```sh
python3 scripts/equation_ledger.py --check --historical
python3 -m unittest discover -s tests -p "test_equation_ledger.py"
```

`--historical` checks the archived source, dependency manifest and [audit program](equation-baseline-axiom-audit.lean.txt) against the original accepted hashes. It still checks the live manuscript and toolchain against their accepted hashes. It neither installs the archived manifest nor changes the current dependency selection. This is historical evidence only, not current-source coverage. The default live-source `--check` intentionally fails when the current source or manifest differs from the reviewed snapshot.

The current production declarations can be inspected separately with the current committed dependencies:

```sh
lake build AsymmetricTensor
lake env lean tests/EquationAxioms.lean > /tmp/current-equation-axioms.log
```

That current-source log must not overwrite the historical audit. Historical mode rejects `--audit-log`. To independently reproduce the archived kernel audit, use a separate checkout whose live source, manifest, PDF, toolchain and audit program all match the accepted snapshot hashes, then run the Lean audit and `python3 scripts/equation_ledger.py --audit-log /tmp/equation-axioms.log --check` there. Never replace the current repository manifest to make the old ledger pass.

`--check` also works without `--audit-log` in a matching snapshot checkout to check the committed audit and deterministic artifacts. `pdftotext` (Poppler) is required. `--write --historical` can regenerate presentation from the preserved reviewed evidence; it does not update the accepted hashes or reclassify equations for current code. A changed evidence source, PDF, toolchain, manifest or audit program fails rather than silently inheriting prior coverage claims. For a new current-source ledger, manually review equation mappings and hypotheses, update snapshot hashes, rebuild, rerun the full audit, and regenerate; do not mechanically copy these historical statuses.
