# Optional native DotOK work-order template

This is an unexecuted example. The YAML uses only native DotOK fields. Paste into the canonical PR thread/issue if useful, or use as a derived `.tasks` execution mirror. Most human contributors can use a plain checklist instead.

Canonical task: <verified PR-thread/issue permalink>
Subject: <repository; main or PR; exact head/base/source identity>
Owner and authority: <accepted owner or unclaimed; applicable approval>
Deliverable: <one bounded result>
Next action: <one executable step>
Verification: <command/review and expected acceptance outcome>
Result: <evidence URL and exact revision, or unknown/pending>

For an author-dependent leaf only, add the actual day's `task-needs-attention-YYYY-MM-DD` to `blocked_by` and link its exact question in the single daily digest. Do not use `status: blocked`, and do not add a user blocker directly to a high/medium task.
